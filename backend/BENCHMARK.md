# Сравнение агентов и решение о версии для сдачи

Дата: 23 сентября 2026. Запуски: официальный `local_eval.evaluate_agent`,
пакет участника без изменения скоринга. NumPy 2.3.5, pandas 3.0.1.

## 20 запусков на одинаковых seed

Использованы два набора: 0–9 и 100–109. Второй набор проверен после реализации,
без подбора параметров по его результатам. Изменяется шум пилотов, а не истинные
эффекты мок-среды. Одинаковый seed не означает одинаковый состав пилотных
выборок: стратегии совершают разные последовательности действий.

| Агент | Средний чистый результат | Худший результат | Положительные запуски |
|---|---:|---:|---:|
| Стартовый `agent_template.py` | −602 428 | −1 264 595 | 0/20 |
| Основной `agent.py` | +2 495 063 | +1 777 371 | 20/20 |
| Экспериментальный `agent_confirmed.py` | +2 323 132 | +1 662 735 | 20/20 |

Среднее преимущество основного агента над шаблоном: **+3 097 491 у.е.**
Это разница чистых результатов, не увеличение общей выручки в несколько раз.
Числа округлены; полные наблюдения находятся в `benchmark_results.json` и
`benchmark_holdout.json`. Никаких гарантий результата на скрытой среде эти
измерения не дают.

## Почему основным оставлен agent.py

Экспериментальная версия резервирует до четырёх пилотов для прямой проверки
дорогих каналов и не включает непроверенный дорогой канал в финальный план.
Наблюдения разных каналов разделены. Отдельный тест с отрицательным эффектом
дорогого канала показывает, что агент отказывается от него.

Но разведка расходует бюджет. На двух наборах официальных seed эксперимент
проиграл основной версии; его средний результат примерно на 6.9% меньше.
Поэтому **эксперимент не заменяет основной агент**. Он сохранён как проверенная
альтернатива для дальнейшего исследования с другими эффектами. Тест отказа
от плохого канала проверяет поведение, а не доказывает превосходство на всех
вариантах среды. Подбора констант по скрытым таблицам не было.

## Воспроизведение

Все команды выполняются из папки с пакетом участника, в репозитории — `backend`.

```shell
python -m unittest -v test_agent.py test_agent_confirmed.py
python benchmark.py --runs 10
python benchmark.py --runs 10 --start-seed 100 --output benchmark_holdout.json
python local_eval.py
python make_submission.py
python export_demo.py
```

Для единичного запуска экспериментальной версии без замены файла сдачи:

```shell
python -c "from agent_confirmed import Agent; from local_eval import evaluate_agent; evaluate_agent(Agent(), seed=42)"
```

`benchmark.py` не импортирует скрытые функции среды: он вызывает официальный
оценщик как внешний тестовый инструмент. `agent.py` и `agent_confirmed.py` не
импортируют оценщик или мок-модель вообще.

## Подключение отчёта к существующему API

Текущий API вызывает `build_submission(Agent(), seed=42)`. Чтобы не потерять
отчёт, сохранить экземпляр агента и добавить `report` к существующему ответу:

```python
agent = Agent()
df = build_submission(agent, seed=42)
report = agent.report
# В существующий JSON-ответ добавить: "report": report.
```

Не запускать агента второй раз для отчёта: бюджет, пилоты и CSV должны относиться
к одному запуску. Для примера фронтенду уже создан `demo_report.json`.

Поля `resources.budget_after_pilots` и `budget_after_plan` различаются: среда
расходует ресурсы во время пилотов, а финальные кампании возвращаются как план.
`estimated_ratio` и `uncertainty` — прогнозы; `estimate_basis` объясняет, получена
ли оценка прямым пилотом или переносом множителя канала. Ни одно из этих полей
не следует подписывать как фактическую прибыль. Фактический результат доступен
в отдельном отчёте официального оценщика.
